# How We Cut Agent Latency 40% With Prompt Caching

In high-throughput multi-agent systems, context re-evaluation is one of the highest contributors to both latency and token expenditure. When multiple specialized agents (e.g., script breakdown, asset matching, audio rendering, safety filters) exchange state across sequential graph steps, large system prompts and conversation histories are repeatedly re-processed by the LLM inference provider.

In this video breakdown and accompanying technical notes, we walk through how we implemented deterministic prompt prefix structuring and prompt caching across our agentic graph, yielding a **40% reduction in end-to-end latency** and a **55% drop in input token overhead**.

---

## Key Technical Takeaways

### 1. Static Prefix Alignment
Prompt caching relies on exact prefix matching at the token layer. By ordering agent system prompts with static instructions first and dynamic variables (user context, execution IDs) at the tail of the message array, LLM providers reuse KV cache blocks across turns.

```python
# Before (Cache Miss Every Step)
messages = [
    {"role": "system", "content": f"Session ID: {session_id}. You are a video editing agent..."},
    {"role": "user", "content": prompt}
]

# After (Cache Hit Rate > 85%)
messages = [
    {"role": "system", "content": STATIC_SYSTEM_PROMPT},
    {"role": "user", "content": f"Context: {session_id}\n\nTask: {prompt}"}
]
```

### 2. Multi-Agent Graph State Checkpointing
Instead of appending full conversation histories into every sub-agent, we slice checkpoint states so each sub-agent only receives the minimal schema needed to complete its sub-graph computation.

### 3. Measured Benchmarks
- **P50 Latency**: Reduced from 4.2s to 2.4s per step.
- **P99 Latency**: Reduced from 8.8s to 5.1s.
- **Cache Hit Ratio**: 88.4% across 10,000 synthetic test runs.
